# ADR 008: soft delete и историческая видимость в contract

**Статус:** принято.

## Контекст

Задание требует soft delete справочников и отдельно требует, чтобы удалённый по запросу клиент исчезал из аналитики. При этом исторические чеки, партии, закупки и движения продолжают ссылаться на SKU, pharmacy, supplier и DC.

Простое правило `WHERE deleted_at IS NULL` во всех contract views ломает историческую ссылочную целостность и проверки C07/C08/X01/X03/X06.

## Рассмотренные варианты

1. **Скрывать все soft-deleted сущности из contract.** Отвергнуто: исторические факты становятся orphaned с точки зрения интеграционного интерфейса.
2. **Никого не скрывать.** Отвергнуто для customer: это противоречит явному требованию задания об исчезновении клиента из аналитики.
3. **Разделить semantics master-data и customer deletion.** Выбрано.

## Выбор

- SKU, pharmacy, supplier, DC и reference values после soft delete остаются доступны в contract;
- их неактивность отражается через `is_active=false`;
- CHECK запрещает состояние `deleted_at IS NOT NULL AND is_active=true`;
- customer — специальное исключение: исчезает из `contract.v_customer`, а PII-контакты обезличиваются.

## Цена выбора

Soft delete имеет неодинаковую семантику по сущностям, поэтому её нужно явно документировать для DWH/CDC. Для customer простая watermark-выгрузка только из contract view недостаточна: исчезновение строки требует отдельной обработки tombstone/изменения source table.
