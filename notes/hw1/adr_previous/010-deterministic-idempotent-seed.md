# ADR 010: deterministic и idempotent seed через namespace business keys

**Статус:** принято.

## Контекст

HW1 требует большой согласованный dataset, повторяемость `--seed N`, идемпотентный повторный запуск и возможность добавить новую порцию данных для проверки репликации.

Генератор работает сразу с четырьмя независимыми БД, поэтому случайно сгенерированные отдельно ключи быстро ломают cross-service references.

## Рассмотренные варианты

1. **Генерировать random UUID/значения при каждом запуске.** Отвергнуто: повторный seed не воспроизводим и не идемпотентен.
2. **Перед каждым seed очищать базы и загружать всё заново.** Отвергнуто: не проверяет append/delta сценарий и мешает replication checker.
3. **Детерминированный namespace, общий generation context и idempotent inserts.** Выбрано.

## Выбор

Base и delta generation используют явный `--seed` как namespace business keys. Один seed воспроизводит тот же логический dataset; повтор того же seed не добавляет строки второй раз.

Cross-service BK создаются в общем generation context и затем переиспользуются Catalog/CRM/WMS/POS, а не придумываются каждым сервисом независимо.

Для replication checker `seed_delta` получает новый namespace из `infra.delta_seed_seq` и добавляет новую порцию данных поверх существующей.

## Цена выбора

Генератор сложнее простого набора случайных INSERT: нужно контролировать порядок зависимостей и namespace. Зато данные воспроизводимы, пригодны для тестов репликации и не требуют destructive reset.
