## Согласования между участниками

1. Сохранить имена четырёх service_db и контракт `contract.*`.
2. Исправления схемы оформлять новыми нумерованными SQL-файлами, если старые
   уже применены. Каждый файл транзакционный; новые зависимости PostgreSQL
   или Python сообщать владельцу инфраструктуры.
3. Генератор остаётся вызываемым как `python -m pharmacy_dwh.seed.cli`.
4. Права app — DML бизнес-таблиц; если новая логика требует дополнительных
   schema/function privileges, добавить их в configure_access_and_cdc.

Ошибки закупок, I9, удаления клиентов и смен сейчас не блокируют написание
Compose, образов и маршрутизации. Они будут влиять на конечные данные и итог
проверки; инфраструктура их автоматически не исправляет.

## Включение в командный репозиторий

Архив выдачи содержит полный snapshot проекта и отдельный `infrastructure.patch`.
Если продолжать работу в уже существующем репозитории, удобнее применить патч
на отдельной ветке, а не заменять весь каталог.

```bash
git switch -c hw1-infra
git apply --check /path/to/infrastructure.patch
git apply /path/to/infrastructure.patch
```

Команды запускаются из корня командного репозитория. Если ветка уже содержит
изменения тех же Compose/README/обёрток, перенести их обычным merge/review;
патч намеренно не должен молча затирать новые изменения команды.

Обновлённые manifests сохраняют сведения о трёх участниках и solo=false.
Третий GitHub login отсутствовал в исходных данных — команда должна его дописать
в `hw01_submission.dev.yaml` и затем пересоздать оба HA-манифеста либо изменить
их согласованно. Итоговая сдача курса — ветка `hw1`.

## Проверено сейчас

Только синтаксис YAML/Python/shell, пути COPY, существование файлов тестов,
маршруты в manifests, отсутствие циклов depends_on и конфликтов host ports,
неизменность 45 файлов домена/тестов/условия. Минимальный предложенный патч
совместимости checker/Patroni проверен на применимость, но не применён.

## Не выполнено

Сборка Dockerfile, скачивание образов, запуск контейнеров, выполнение миграций,
генерация данных в PostgreSQL, официальный checker на HA, тесты прав,
failover/switchover/etcd quorum, нагрузочные измерения. Их результаты
не подменены предположениями; журнал отказов остаётся пустым шаблоном.

Доменная документация ERD/четыре обязательные темы ADR/DWH mapping остаётся
отдельной задачей команды. Добавленный ADR 005 описывает только инфраструктуру.
