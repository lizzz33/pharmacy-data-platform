# ADR 006: не хранить производные значения как независимое физическое состояние

**Статус:** принято.

## Контекст

Контракт требует несколько значений, которые полностью выводятся из других данных.

Если хранить и исходные поля, и результат вычисления, появляются два источника истины.

## Рассмотренные варианты

1. **Физически хранить каждое поле contract.** Отвергнуто: вычисляемое значение может разойтись с исходными.
2. **Generated columns для всего.** Не подходит для значений, зависящих от JOIN или aggregate.
3. **Хранить минимальное исходное состояние и вычислять производные значения в contract views.** Выбрано.

## Выбор

Физически не храним:

- `receipt_line.line_amount` — `quantity * unit_price - line_discount`;
- `receipt.discount_amount` — агрегат discount по строкам;
- `purchase_line.line_cost` — `quantity * unit_cost`;
- отдельный `purchase_line.received_at` — берётся из `batch.received_at`.

## Цена выбора

Contract views становятся немного сложнее и часть вычислений выполняется при чтении.

Зато нет риска рассинхронизации дублированных значений.
