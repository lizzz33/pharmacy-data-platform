# ADR 005: учебный HA-кластер и исполнение миграций

Статус: принято для реализации, эксплуатационная проверка впереди.

## Контекст

HW1 требует физическую реплику и PgBouncer; полная основная часть — три
PostgreSQL под Patroni, etcd и HAProxy. Доменный SQL дорабатывает другая часть
команды. Имена БД и contract API уже определены.

## Рассмотренные варианты

1. Сначала собрать primary/standby вручную, затем перейти на Patroni.
   Отвергнуто: два способа bootstrap и две конфигурации маршрутизации увеличат
   работу при объединении веток.
2. Запускать миграции через docker-entrypoint-initdb.d каждого PostgreSQL.
   Отвергнуто: initdb управляет Patroni, а SQL требуется выполнять на лидере,
   не независимо на всех узлах.
3. Один etcd вместо трёх.
   Отвергнуто для итогового варианта: потеря единственного DCS лишает кластер
   координации и не позволяет изучить сохранение кворума после отказа одного узла.

## Выбор

Три PostgreSQL 16 под Patroni, три etcd, HAProxy RW/RO и два PgBouncer.
Отдельный db-init применяет транзакционные миграции на лидере и хранит SHA-256.
Репликация по умолчанию асинхронная. Для репликации используются managed slots;
для восстановления бывшего лидера включены checksums и pg_rewind.

PgBouncer работает в session mode ради сессионных SET официального чекера.
Transaction pooling отвергнут как default: его работа с произвольным
statement_timeout/другими SET потребовала бы менять поведение проверяющего.

## Цена выбора

Девять постоянно работающих контейнеров, больше памяти и конфигурации.
Session pooling ограничивает выигрыш для большого числа долгоживущих клиентов.
Асинхронность допускает потерю подтверждённых транзакций при аварии лидера;
фактическая потеря и RTO будут измерены позже. Один хост остаётся общей точкой
отказа. HAProxy и PgBouncer в этом учебном варианте также не дублируются.
Конфигурация не заменяет резервное копирование и восстановление после ошибок.

## Валидация

Пока только YAML, Python AST, shell syntax и статические связи файлов.
Образы/кластер/SQL/промоут/CDC и failover не запускались.
